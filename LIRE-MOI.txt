SPORTS BET — Automatique, sans mails

INSTALLATION SUR ORDINATEUR
1. Extraire le ZIP.
2. Ouvrir https://github.com/pascal0608/SportsBet
   Code > Add file > Upload files. Glisser tout le contenu extrait,
   y compris le dossier .github, puis Commit changes.
   Remplacer les fichiers existants. Ne pas importer le ZIP lui-même.
3. Settings > Pages > Source : GitHub Actions.
4. Actions > Actualiser les matchs et resultats FDJ > Run workflow.
   Attendre la coche verte. Site : https://pascal0608.github.io/SportsBet/

Si .github n'a pas été importé : Code > Add file > Create new file.
Nom complet : .github/workflows/fdj.yml
Coller le contenu du fichier fdj.yml fourni, puis Commit changes.
sync_fdj.py doit être à la racine du dépôt.

FONCTIONNEMENT
GitHub récupère les données publiques FDJ environ toutes les 15 minutes.
Les tâches peuvent être retardées : ce n'est pas un flux en direct.
L'application les charge à chaque ouverture et avec Actualiser la liste.
Les matchs fermés disparaissent des choix ; les tickets restent conservés.
Seuls les identifiants exacts événement/marché/sélection et les statuts
officiels confirment un résultat. Un résultat inconnu reste en attente.
Les données de plus de 45 minutes bloquent les nouveaux tickets officiels.
La date des données et les éventuelles compétitions partielles sont affichées.
Les cotes virtuelles conservent la majoration de 7 % de la première version.

Tickets et crédit restent dans ce navigateur, sans synchronisation ChatGPT.
Utiliser Sauvegarder mes données pour les exporter. Les matchs manuels
gardent leurs résultats manuels ; les résultats FDJ sont automatiques.
Aucun mail. Simulation : aucun gain réel.

Les échecs sont visibles dans Actions. Les dernières données sont conservées.
GitHub peut suspendre la programmation après 60 jours sans activité du dépôt :
la réactiver dans Actions si nécessaire.
